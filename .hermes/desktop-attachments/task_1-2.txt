==================================================

Cloudflare R2 lưu:

- IELTS Reading test data
- IELTS Listening test data
- IELTS Speaking content pools
- IELTS Writing prompts
- Cambridge Reading/Listening static content nếu đang dùng cùng data layer
- passages
- transcripts
- audio
- images
- catalogs
- manifests

Supabase tiếp tục lưu:

- authentication
- user profiles
- progress
- user answers
- scores
- bookmarks
- saved decks
- subscriptions/permissions
- dữ liệu quan hệ hoặc dữ liệu người dùng

Không đưa user-generated data sang bucket public.

==================================================
5. CONTENT SCHEMA
==================================================

Tái sử dụng schema/type hiện tại nếu hợp lệ.

Mỗi test object phải có tối thiểu:

{
  "schemaVersion": 1,
  "id": "stable-test-id",
  "skill": "reading",
  "level": "c1",
  "title": "...",
  "parts": [...],
  "assets": [...]
}

Không serialize:

- React elements
- functions
- Map
- Set
- undefined
- local filesystem paths
- secrets

Mọi asset reference phải là relative object path hoặc HTTPS URL hợp lệ.

==================================================
6. ANSWER KEY SECURITY
==================================================

Audit xem answer keys hiện đang nằm ở đâu.

Nếu answer keys hiện đã được ship trong frontend bundle thì ghi nhận hiện trạng,
nhưng không làm mức bảo mật kém hơn.

Ưu tiên:

- Public R2:
  questions, passages, images, audio, transcripts cần thiết.
- Private R2 hoặc backend:
  answer keys và scoring metadata cần bảo vệ.

Không đưa R2 secret vào frontend.

Nếu private answer key chưa thể triển khai trong task này:

- Giữ scoring source hiện tại.
- Không block migration public content.
- Báo rõ remaining work.

==================================================
7. EXPORT PIPELINE
==================================================

Tạo script idempotent, ví dụ:

scripts/content/export-exam-content.mjs

Script phải:

1. Đọc data source hiện tại.
2. Validate schema.
3. Tách mỗi test thành một JSON riêng.
4. Copy audio/images vào staging directory.
5. Tạo catalog theo skill/level.
6. Tạo release manifest.
7. Tạo SHA-256 cho từng object.
8. Ghi inventory.
9. Không upload nếu validation fail.

Output local:

tmp/r2-release/<release-id>/

Tạo:

tmp/r2-release/<release-id>/inventory.json

Inventory gồm:

- object key
- bytes
- sha256
- content type
- cache policy
- source module

==================================================
8. VALIDATION TRƯỚC UPLOAD
==================================================

Bắt buộc kiểm tra:

- Unique test IDs
- Unique question IDs
- Correct question counts
- Correct answer counts
- Không missing asset
- Không local absolute path
- Không undefined/null ngoài schema
- Không empty catalog
- JSON parse được
- Audio files có bytes > 0
- Image files có bytes > 0
- Content-Type đúng

Tạo guard theo từng module:

- IELTS Reading entries/questions/answers
- IELTS Listening entries/questions/audio
- IELTS Speaking Part 1/2/3 counts
- IELTS Writing entries/tasks
- Cambridge Reading/Listening counts

Build phải fail nếu module từng có dữ liệu mà export mới trở thành 0.

==================================================
9. UPLOAD R2
==================================================

Tạo upload script dùng:

- Wrangler nếu repository đã dùng Wrangler; hoặc
- S3-compatible R2 API trong script server-side.

Không thêm dependency nếu công cụ hiện tại đã đủ.

Upload theo release prefix trước:

releases/<release-id>/...

Sau khi upload:

- HEAD hoặc GET kiểm tra từng object quan trọng.
- So sánh Content-Length.
- So sánh checksum khi khả dụng.
- Kiểm tra Content-Type.
- Kiểm tra CORS.

Chỉ cập nhật:

manifests/production.json

SAU KHI toàn bộ release objects đã upload và xác minh.

Manifest production phải được publish cuối cùng để release gần atomic.

Không xóa release cũ ngay.

10. CACHE CONTROL
==================================================

Release objects immutable:

Cache-Control:
public, max-age=31536000, immutable

Production manifest:

Cache-Control:
public, max-age=60, must-revalidate

Catalog có release path:

public, max-age=31536000, immutable

Không cache production manifest một năm.

==================================================
11. FRONTEND DATA LAYER
==================================================

Tạo shared loader, ví dụ:

src/services/examContent/
  contentClient.ts
  contentManifest.ts
  contentSchemas.ts
  contentCache.ts

Frontend env:

VITE_EXAM_CONTENT_BASE_URL
VITE_EXAM_CONTENT_MANIFEST

Không hard-code localhost.
Không hard-code bucket development URL trong production code.

Loader phải:

- fetch production manifest
- resolve release object URL
- fetch catalog
- fetch test object khi người dùng mở test
- cache requests trong memory
- hỗ trợ AbortSignal
- báo lỗi có module/test ID
- không swallow 404
- không trả empty array giả khi request fail

12. DUAL-READ MIGRATION
==================================================

Trong giai đoạn chuyển đổi, dùng feature flag:

VITE_EXAM_CONTENT_SOURCE=r2

Allowed:

- r2
- legacy

Không tự fallback im lặng từ R2 sang legacy trong production vì có thể che lỗi
deploy.

Có thể bật fallback chỉ trong development và phải log rõ source.

Migrate theo từng module:

Phase 1:
- một IELTS module representative

Phase 2:
- toàn IELTS

Phase 3:
- Cambridge static content

Sau mỗi phase phải browser-test trước khi chuyển module tiếp theo.

==================================================
13. PRODUCTION ISSUE DIAGNOSIS
==================================================

Điều tra cụ thể vì sao ngân hàng IELTS hiện không xuất hiện trên production.

Ghi lại:

- Route
- Request URL
- HTTP status
- Response body/error code
- Data source selected
- Environment variable values đã mask
- Catalog count local
- Catalog count production

Phân biệt:

- 404 object missing
- CORS
- wrong custom domain
- wrong object key/case
- stale manifest
- Vercel env missing
- Supabase relation missing
- RLS 401/403
- empty seed table
- generated file excluded from deployment

Không kết luận “do Supabase” nếu Network evidence không chứng minh.

15. CORS
==================================================

R2/custom domain phải cho phép frontend production:

https://ryanenglishv2.vercel.app

Nếu dùng preview deployments, cấu hình policy phù hợp nhưng không mở credentials
tùy tiện.

GET/HEAD cần hoạt động.

Allowed headers tối thiểu:

- Content-Type
- Range nếu audio cần seek

Expose headers khi cần:

- Content-Length
- Content-Range
- ETag

Listening audio phải hỗ trợ range requests hoặc cách phát audio hiện có.

==================================================
19. DEFINITION OF DONE
==================================================

Chỉ báo PASS khi:

- R2 release upload hoàn chỉnh.
- Production manifest hợp lệ.
- IELTS content counts khớp local.
- Reading hoạt động từ R2.
- Listening audio/images hoạt động từ R2.
- Speaking/Writing load từ R2 nếu trong scope.
- Production Vercel dùng đúng R2 env.
- Không phụ thuộc Supabase cho static exam content.
- User progress vẫn lưu đúng vào Supabase.
- Không có secrets trong frontend.
- Console errors = 0.
- Network errors = 0.
- TypeScript PASS.
- Production build PASS.
- Content validation PASS.
- git diff --check PASS.
- Có rollback procedure.
