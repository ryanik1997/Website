PHASE 5 — PASSAGE NORMALIZATION
==================================================

Nếu root cause nằm ở parser, sửa normalization thay vì chỉ CSS.

Normalized structure phải giữ paragraph boundary:

type GappedTextSegment =
  | {
      type: "text";
      text: string;
    }
  | {
      type: "gap";
      questionId: string;
      questionNumber: number;
    };

type GappedTextParagraph = {
  id: string;
  segments: GappedTextSegment[];
};

Ví dụ:

{
  id: "p3",
  segments: [
    { type: "text", text: "In those early days..." },
    { type: "gap", questionNumber: 41, questionId: "..." },
    { type: "text", text: "How did they do that?..." }
  ]
}

Không normalize thành:

[
  { type: "paragraph", text: "..." },
  { type: "gap", questionNumber: 41 },
  { type: "paragraph", text: "..." }
]

nếu gap vốn nằm trong cùng paragraph.

Không làm mất:

- punctuation trước gap;
- punctuation sau gap;
- dấu ngoặc kép;
- dấu chấm;
- paragraph boundary;
- khoảng trắng hợp lệ.

Thêm DEV invariant:

- mỗi gap 41–46 xuất hiện đúng một lần;
- không gap nào đứng ngoài paragraph nếu source không yêu cầu;
- không paragraph rỗng được tạo quanh gap;
- không duplicate punctuation.
